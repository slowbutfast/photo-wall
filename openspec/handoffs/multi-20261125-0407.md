### Change 2: `upload-chronological-order`

- **Change directory:** `openspec/changes/upload-chronological-order`
- **Architecture & technical boundaries:**
  - Capture time is read **client-side from the original `File`**, before `prepareUploadFile`. Compression and the server's `sanitizeImage` both strip EXIF.
  - **D1:** a pure module `captureTime.ts` exports `readCaptureTime(bytes): { key: 'YYYYMMDDHHMMSS'; subSec } | null`, `compareCapture`, and `orderByCaptureTime(items, readBytes)`, plus a browser adapter `readCaptureBytes(file)`.
  - **D2:** JPEG `APP1` `Exif\0\0`, PNG `eXIf` (stop at `IDAT`), and WebP `EXIF` (tolerate an `Exif\0\0` prefix), all feeding one bounds-checked TIFF IFD walk.
    - **Tag order:** `0x9003` > `0x9004` > IFD0 `0x0132`, plus `0x9291` sub-seconds.
    - The all-zero placeholder and malformed shapes count as `null`, and the reader never throws.
  - **D3:** JPEG/PNG read `file.slice(0, 256 KiB)`; WebP reads the full file. Type is sniffed from magic bytes.
  - **D4:** compare local wall-clock time; ignore `OffsetTimeOriginal`.
  - **D5:** the order is dated before undated, then key, then sub-seconds as a decimal fraction (missing counts as `.0`), then `Intl.Collator(undefined, { numeric: true, sensitivity: 'base' })`, then the original index.
  - **D6:** `beginUpload` calls `splitAlbumCap(await orderByCaptureTime(group.files, readCaptureBytes), MAX_PHOTOS_PER_ALBUM)`. A `readBytes` failure for a file makes that file undated. Nothing else in the uploader changes.
  - **D7:** no server, schema or API change. The existing `sortOrder` form field carries the rank.
  - `+ Add Print` (`AlbumEditor.tsx`) is unchanged.
- **Visual & UI specifications:** **non-visual change.** No styling, markup or notice changes.
- **Target Context Map:**

### Change 3: `placard-soundtrack-marquee`

    - `distancePx = ceil(textWidth) + gapPx`
    - `durationMs = holdMs + distancePx / speed * 1000`

## 4. Sequential Execution Loop (Execute for i = 1 .. 3)

For each change `<change-i>` in order `1 .. 3`:

1. **Pre-flight check:**
   - Confirm `git status` is clean, apart from the untracked `.playwright-mcp/` and `openspec/changes/mobile-touch-compatibility/` if present. Never stage either.
   - Check the Cross-Change Isolation Matrix. All three changes are `ISOLATED`, so an earlier `BLOCKED` change does not halt the later ones.
2. **Delegate implementation to `spec-coder-sub`:**
   - Instruct it to implement `<change-i>` strictly within its Target Context Map, using Vertical Slice Architecture, the TDD rule (Group 1 failing tests first), real-time `tasks.md` updates, and generation of `<changeDir>/verification.md`.
   - `spec-coder-sub` must NOT create git commits or switch branches.
3. **Verify the implementation (`openspec-verify-change`):**
   - Confirm every ticked checkbox in `<changeDir>/tasks.md` genuinely ran and passed.
   - Confirm `<changeDir>/verification.md` is populated: Requirement Adherence Audit Matrix covering every scenario, resolved assumptions, nomenclature audit, verbatim logs.
   - Run **`openspec-verify-change`** for `<change-i>`.
4. **Single bounded repair pass (max retries = 1):**
   - If CRITICAL issues or test failures appear on the first pass, announce: `"Change '<change-i>' verification failed on initial pass. Attempting a single bounded repair pass via spec-coder-sub..."`
   - Delegate **1** targeted repair task to `spec-coder-sub`, with the verbatim failure log and instructions to make minimal patches and re-run verification.
   - Re-run `openspec-verify-change`.
5. **Gate, atomic commit, or isolation-aware continuation:**
   - **If it passes with zero CRITICAL issues:**
     1. Sync specs: `openspec specs apply --change "<change-i>"`.
     2. Stage **explicit paths only** and commit:
        ```bash
        git add openspec/changes/<change-i> openspec/specs <implementation-files-from-the-map>
        git commit -m "feat(<change-i>): implement and verify change"
        ```
     3. Record **`PASSED`** (commit SHA, and whether the repair pass was used), then proceed.
   - **If it still fails after the single repair pass:**
     - If the failure breaks the shared build or types globally, **HALT** and report.
     - Otherwise, because all changes are `ISOLATED`, stash only this change's paths: `git stash push -m "wip-blocked-<change-i>" -- <change-i target paths> openspec/changes/<change-i>`. Record **`BLOCKED (stashed after 1 repair pass)`** and proceed.
