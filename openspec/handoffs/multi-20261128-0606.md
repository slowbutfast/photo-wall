### Change 1: `soundtrack-playback-sync`

- **Change directory:** `openspec/changes/soundtrack-playback-sync`. Read every artifact. `research.md`'s glossary is binding: `playing` now means the player reported PLAYING.
- **Architecture and technical boundaries** (architecture.md D1–D6):
  - **D1. Bridge:**
    - A raw postMessage bridge to `https://www.youtube-nocookie.com`.
    - The embed gets `enablejsapi=1&origin=<encoded location.origin>`.
    - Post `{"event":"listening","id":"<albumId>","channel":"widget"}` on iframe `load`, and retry every 250 ms until the first message (3 s max).
    - Accept messages only where `origin === 'https://www.youtube-nocookie.com'` **and** `source === iframe.contentWindow`.
    - **No `iframe_api` script. `csp.ts` must not change.**
  - **D2. Reducer:**
    - `play` mounts the player with `playing: false`.
    - New album-scoped `player-state` event: `1` sets `playing` true; `-1`, `2`, `3`, `5` set it false; `0` goes through `track-ended`.
    - New `bridge-unavailable` event sets `playing: true` (the legacy fallback).
    - A no-op returns the identical object.
  - **D3. Clock:**
    - A separate `soundtrackClock { albumId, positionSec, at }` key in `useWallStore`.
    - It's reset whenever `activeAlbumId` changes.
    - Writes are throttled to state changes or more than 0.75 s of drift.
    - `GalleryCanvas`'s `state.soundtrack` selector must keep its identity across clock writes.
  - **D4. Timecode:** `PlacardTimecode` interpolates `positionSec + (now − at)/1000` with a 250 ms interval, clamped to `[0, durationSec]`.
  - **D5. Refusal:** if there's no `1` or `3` within 1500 ms of the first bridge message and the last state is `-1` or `5`, dispatch `lift-capture-layer`.
  - **D6. Debug:** `?debugSoundtrack=1` turns on `console.info` logging.
- **Visual and UI specifications:** non-visual and behavioural. Don't add CSS or DOM. The timecode value table is in design.md.
